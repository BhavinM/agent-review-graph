🚀 Day 2 of building with Jev (TypeSafe AI): I built a semantic linter for AI agent skills.

Yesterday (Day 1), I shared the Jev Policy Engine for runtime enforcement. But runtime guardrails are only half the battle. 

What happens when your team writes agent rules that contradict each other BEFORE they ever hit production?

For example:
• Agent A (search_agent.md): "MUST ALWAYS ask for explicit user permission before executing a search."
• Agent B (background_researcher.md): "MUST NEVER ask the user for permission to search."

Both are plain English. Both live in your repository. Neither will break a standard linter or unit test. But when deployed, your system enters an infinite loop or security deadlock.

So today, I built AgentReviewGraph 🕵️‍♂️🕸️ — a CLI policy linter for AI agent skill files.

Here is how it works under the hood:

1️⃣ Semantic Knowledge Graph: Parses Markdown skill files into a strictly typed graph of Skill Nodes and Constraint Edges.
2️⃣ Jev-Powered Contradiction Engine: Passes constraints to TypeSafe AI's Jev (System One) engine to detect semantic conflicts with a severity score (0.0 to 1.0).
3️⃣ Canonical Domain Tagging (The O(1) Trick): Jev tags every constraint by domain (e.g., Web Search, Security, Billing). The engine only compares rules within the same domain — eliminating 90%+ of wasteful API calls at scale.
4️⃣ Adaptive Recursive Batching: Batches up to 10 pairs per API request, self-healing under rate limits.
5️⃣ Local CLI & CI/CD Gate: Run it locally anytime (`agent-review ./skills`), or pass `--fail-on-contradiction` in GitHub Actions to block broken PRs with Exit Code 1.
